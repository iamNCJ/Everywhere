# Global Agent Session Memory — Design Spec

**Date:** 2026-04-29  
**Status:** Approved

---

## Overview

A system that automatically persists structured, hierarchical memory from every Claude Code (and future Codex) session to a local + remote-synced Git repository. Enables cross-session retrieval and optional context injection into any new session.

---

## Goals

- Zero-friction session capture: no manual action required under normal conditions
- Resilient: survives CC being killed mid-session via periodic snapshots
- No main-session token pollution: summarization runs in an isolated async agent (Haiku)
- Hierarchical storage: project-level summaries + per-session detail
- Searchable: Claude can search the memory repo on demand from any session
- Synced: local Git repo pushed to a remote (GitHub)

---

## Architecture

### Trigger Chain

```
Stop hook (async, debounced per session)
    → check ~/.agent-memory/.snapshots/.last-{session_id} timestamp
    → if > 10 min since last save AND session has new content
        → spawn async Haiku agent
            → read session transcript
            → write/overwrite incremental snapshot to local memory repo
            → update timestamp file

SessionEnd hook (async)
    → spawn async Haiku agent
        → read full session transcript
        → generate final complete structured summary
        → overwrite session directory with complete version
        → update PROJECT.md and INDEX.md
        → git add + commit + push
        → delete timestamp file
```

**Key invariant:** Stop snapshots are idempotent (always overwrite same session dir). SessionEnd upgrades the last snapshot to a final version and syncs to remote.

## Storage Structure

### Memory Repo (`~/agent-memory/`)

```
~/agent-memory/
├── INDEX.md                              # Global cross-project index (injected by /memory on)
├── global/
│   └── cross-session-insights.md        # High-value insights spanning projects
└── projects/
    └── {project-name}/                  # e.g. workspace-dev
        ├── PROJECT.md                    # Continuously updated project-level summary
        └── sessions/
            └── {date}-{session_id_short}/
                ├── meta.yaml            # Session metadata (see below)
                ├── summary.md           # L1: 3-5 sentence high-level summary
                ├── decisions.md         # L2: Key technical decisions and rationale
                ├── artifacts.md         # L3: Files created/modified, commands run
                └── excerpts.md          # L4: Valuable Q&A fragments for retrieval
```

### `meta.yaml` Schema

```yaml
session_id: abc123def456                        # Full CC session ID (for transcript lookup)
session_id_short: abc123                        # First 6 chars (used in directory name)
project_path: /Users/ncj/Documents/workspace/dev  # Absolute working directory
project_name: workspace-dev                     # Derived from last path component
agent: claude-code                              # Source agent (claude-code / codex)
model: claude-sonnet-4-6                        # Model used in main session
started_at: 2026-04-29T10:23:00Z
ended_at: 2026-04-29T12:15:00Z                 # Null if snapshot (not final)
is_final: true                                  # false for Stop snapshots
snapshot_count: 3                               # How many Stop snapshots preceded final
tags: [kubernetes, auth, debugging]             # Generated by summarizer
```

## Content Hierarchy (per session)

| Level | File | Content | Used by |
|-------|------|---------|---------|
| L0 | `meta.yaml` | Structured metadata, tags, paths | Search filtering |
| L1 | `summary.md` | 3-5 sentence overview | `/recall` quick scan, `PROJECT.md` |
| L2 | `decisions.md` | Technical choices, tradeoffs, gotchas | `/recall` deep dive |
| L3 | `artifacts.md` | Files touched, commands run, PRs/issues | Audit trail |
| L4 | `excerpts.md` | Best Q&A exchanges verbatim | Semantic search |

## Skill: `session-memory`

Lives in `~/.claude/skills/session-memory/SKILL.md`.

### Commands

| Command | Behavior |
|---------|----------|
| `/session-save` | Manually trigger a full save of the current session now |
| `/recall [query]` | Claude searches memory repo (ripgrep + semantic read) and returns relevant hits |
| `/memory on` | Inject `INDEX.md` + current project's `PROJECT.md` into context |
| `/memory off` | Remove injected memory from context |

### `/recall` Search Strategy

1. `ripgrep` on tags and summary files for fast keyword match
2. Claude reads top-N candidate `summary.md` files
3. Expands into `decisions.md` / `excerpts.md` for relevant hits
4. Returns ranked results with session date, project, and relevant excerpt

## Hook Configuration (`~/.claude/settings.json`)

```json
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "agent",
        "model": "claude-haiku-4-5-20251001",
        "async": true,
        "prompt": "...",
        "timeout": 120,
        "statusMessage": "Saving session snapshot..."
      }]
    }],
    "SessionEnd": [{
      "hooks": [{
        "type": "agent",
        "model": "claude-haiku-4-5-20251001",
        "async": true,
        "prompt": "...",
        "timeout": 180,
        "statusMessage": "Finalizing session memory..."
      }]
    }]
  }
}
```

The actual agent prompts are stored in `hooks/stop-snapshot-prompt.md` and `hooks/session-end-prompt.md` in this repo and referenced from the hook command.

## Transcript Access

The hook receives `{"session_id": "..."}` on stdin. The Haiku agent accesses conversation content via:

```bash
~/.claude/sessions/{session_id}   # session transcript directory (primary)
~/.claude/history.jsonl           # fallback: global history log
```

The agent hook has Bash + Read tools available, so it can read these paths directly. The exact transcript format must be validated during implementation — this is the primary technical risk.

---

## Debounce Logic (Stop hook)

Timestamp files live inside the memory repo at `~/agent-memory/.snapshots/` (gitignored).

The Stop hook agent:
1. Reads `~/agent-memory/.snapshots/.last-{session_id}` (timestamp file)
2. If file doesn't exist OR mtime > 10 minutes ago → proceed with snapshot
3. Writes current timestamp to the file after snapshot completes
4. SessionEnd agent deletes the timestamp file as cleanup

This prevents redundant API calls on sessions with many short turns.

---

## Git Sync Strategy

- Local repo: `~/agent-memory/` (initialized once during setup)
- Remote: GitHub private repo (configured once, URL stored in `~/agent-memory/.git/config`)
- Commit message format: `snapshot: {project-name} {session_id_short} ({date})`
- Final commit message: `session: {project-name} {session_id_short} - {first line of summary}`
- Push strategy: `git push` after every final SessionEnd commit; Stop snapshots do NOT push (local only)
